1. Modularidad

Divide y vencerás en el código

¿Qué es la Modularidad?

Es el principio de dividir un sistema masivo en piezas lógicas más pequeñas, independientes y manejables (módulos).

La Analogía: Imagina diseñar una placa PCB en Proteus. No mezclas las pistas de 220V con los pines lógicos. Creas un módulo de alimentación y un módulo de procesamiento separados. Si falla la fuente, solo revisas esa parte, no tiras todo el hardware.

// El problema de no modularizar:
class SistemaMonolitico 
{
    public void LeerSensores() { ... }
    public void ConectarWiFi() { ... }
    public void GuardarBD() { ... }
}

Estructura Sintáctica

En C#, creamos un módulo envolviendo nuestro código con la palabra reservada namespace.

Para interconectar un módulo con otro, usamos la directiva using en la cabecera del archivo.

// Archivo: Sensores.cs
namespace Hardware.Sensores
{
    public class Termometro { ... }
}

// Archivo: Program.cs
using Hardware.Sensores; // Conectando módulo

Termometro t = new Termometro();

Ejemplo Sencillo

Separamos una herramienta matemática básica para que pueda ser reutilizada en cualquier parte del proyecto sin saturar el programa principal.

// Módulo de Utilidades
namespace Herramientas
{
    public class Calculadora 
    {
        public int Sumar(int a, int b) 
        { 
            return a + b; 
        }
    }
}

Ejemplo Complejo

Desarrollo de un sistema IoT. Modularizar permite que el equipo de Redes y el de Electrónica trabajen al mismo tiempo sin que sus variables choquen o generen errores.

// Módulo estrictamente de Hardware
namespace ProyectoIoT.Controladores
{
    public class BombaDeAgua { ... }
}

// Módulo estrictamente de Red
namespace ProyectoIoT.Conectividad
{
    public class ClienteMQTT { ... }
}

Ejercicios: Modularidad

  • Básico: Crea un namespace Geometria con una clase Cuadrado. Importa el módulo en tu Program.cs e instáncialo.
  • Complejo: Modela un sistema de notas universitarias. Crea los módulos Academico (clase Materia) y Usuarios (clases Docente, Estudiante). Importa ambos en el Main y haz que el docente asigne una materia.
// Pista para el ejercicio complejo:
using Universidad.Academico;
using Universidad.Usuarios;

Docente d = new Docente();
Materia m = new Materia();

2. Modificadores de Acceso

Seguridad y Encapsulamiento

¿Qué son y para qué sirven?

Son reglas que protegen las variables sensibles de ser alteradas por accidente (Encapsulamiento).

La Analogía: Un Controlador PID analógico. Tiene perillas externas para que el usuario cambie el SetPoint (Público). Pero sus resistencias y amplificadores operacionales están ocultos dentro de la carcasa (Privado). Si el usuario toca el circuito interno, descalibrará o quemará el sistema.

// El peligro de no encapsular:
public class CuentaBancaria
{
    public double Saldo; // ¡Vulnerabilidad!
}

CuentaBancaria cuenta = new CuentaBancaria();
cuenta.Saldo = -5000; // Alterado externamente

Estructura Sintáctica

  • public: Sin restricciones. Accesible desde cualquier lugar.
  • private: Oculto. Accesible SOLO desde adentro de sus propias llaves.
  • protected: Accesible en su clase y en clases que hereden de ella.
public class Termometro
{
    public string Marca; // Visible para todos
    
    private double _temp; // Circuito interno protegido

    public void Calibrar() 
    {
        _temp = 0.0; // Válido: acceso interno
    }
}

Ejemplo Sencillo

Protegemos la variable utilizando `private`, y obligamos al usuario a interactuar a través de un método `public` que actúa como filtro de seguridad.

public class Motor
{
    private double _rpm; // Protegido

    public void SetVelocidad(double valor)
    {
        if(valor >= 0 && valor <= 3000)
        {
            _rpm = valor;
        }
    }
}

Ejemplo Complejo: Propiedades

En C# moderno, en lugar de crear métodos Get() y Set() por separado, utilizamos Propiedades para encapsular la lógica de manera elegante usando la palabra reservada value.

public class Motor
{
    private double _rpm;

    public double RPM 
    {
        get { return _rpm; }
        set 
        { 
            // 'value' es el dato ingresado
            if(value >= 0 && value <= 3000) 
                _rpm = value; 
        }
    }
}

Ejercicios: Modificadores

  • Básico: Crea la clase CuentaBancaria con un _saldo privado. Crea los métodos públicos Depositar() y Retirar() que validen no introducir montos negativos.
  • Complejo: Crea una clase SistemaLogin con una variable privada _password. Implementa un método público CambiarClave(actual, nueva) que exija verificar internamente la clave antigua antes de cambiarla.
// Pista para el complejo:
public void CambiarClave(string act, string nv)
{
    if (act == _password)
    {
        _password = nv;
    }
}

3. Herencia

Reutilización y Jerarquía de Clases

¿Qué es la Herencia?

Es crear una clase nueva basándose en una existente, absorbiendo todo su código sin necesidad de reescribirlo. Sigue la lógica de "ES UN".

La Analogía: Todo componente electrónico tiene *Fabricante* y *Precio*. Un ESP32 es un componente electrónico. Por tanto, hereda esos datos básicos, pero añade características exclusivas (pines GPIO, módulo Wi-Fi).

// El ESP32 no necesita reescribir variables
Microcontrolador esp32 = new Microcontrolador();
esp32.Fabricante = "Espressif"; // Heredado
esp32.PinesGPIO = 38;           // Propio

Estructura Sintáctica

Para heredar de una clase, colocamos el símbolo de dos puntos : seguido del nombre de la clase Padre.

// Clase Padre (Base)
public class Componente 
{
    public string Fabricante;
}

// Clase Hija (Derivada)
public class Microcontrolador : Componente 
{
    public int PinesGPIO;
}

Ejemplo Sencillo: Constructores y 'base'

Si la clase padre obliga a pedir datos al momento de nacer (en su constructor), la clase hija está obligada a pedirlos también y enviárselos al padre usando base.

public class Persona
{
    public string Nombre;
    public Persona(string nom) { Nombre = nom; }
}

public class Docente : Persona
{
    public string Materia;
    
    // Recibe ambos, redirige 'nom' al padre
    public Docente(string nom, string mat) : base(nom)
    {
        Materia = mat;
    }
}

Ejemplo Complejo: Polimorfismo

Si la clase hija hereda un método del padre, pero necesita ejecutarlo de forma distinta, puede sobreescribirlo. El padre debe usar virtual y el hijo override.

public class DispositivoRed
{
    public virtual void Conectar() 
    { 
        Console.WriteLine("Conexión genérica..."); 
    }
}

public class ModuloWiFi : DispositivoRed
{
    public override void Conectar() 
    { 
        Console.WriteLine("Ingresando clave WPA2..."); 
    }
}

Ejercicios: Herencia

  • Básico: Crea Vehiculo con la propiedad Marca. Crea Moto que herede de Vehículo y agregue Cilindrada. Instánciala y muestra ambos datos en consola.
  • Complejo: Desarrolla un sistema de sueldos. Clase padre Empleado con salario fijo. Clase hija DocentePorHora que sobreescriba con override un método Cobrar() multiplicando las horas por la tarifa.
// Pista para el básico:
Moto ninja = new Moto();
ninja.Marca = "Kawasaki"; // Propiedad heredada
ninja.Cilindrada = 600;   // Propiedad propia

4. Abstracción

Definir el 'QUÉ', delegar el 'CÓMO'

¿Qué es la Abstracción?

Consiste en aislar el comportamiento esencial de un objeto, creando plantillas que obligan a seguir una estructura, ocultando la complejidad técnica.

La Analogía: Conducir un coche. Tú interactúas con los pedales y el volante (la abstracción). No necesitas entender la inyección electrónica ni los pistones (el "cómo" oculto) para que el auto acelere.

// Una clase abstracta es una plantilla incompleta
// ¡Prohibido instanciarla con 'new'!
public abstract class Vehiculo
{
    public void MostrarEstado() { ... }
    
    // Método abstracto: Obliga a los hijos a escribirlo
    public abstract void Acelerar(); 
}

Estructura Sintáctica

Se utiliza la palabra clave abstract.

Un método abstracto no tiene llaves {}, termina en punto y coma. Las clases hijas están obligadas a programar ese bloque de código usando override.

public class Automovil : Vehiculo
{
    // El compilador exige implementar este código
    public override void Acelerar()
    {
        Console.WriteLine("Inyectando gasolina...");
    }
}

Ejemplo Sencillo

Un sistema geométrico. Sabemos que todas las figuras tienen un área, pero la matemática para calcularla depende estrictamente de cada figura.

public abstract class Figura
{
    public abstract double CalcularArea();
}

public class Cuadrado : Figura
{
    public double Lado { get; set; }
    
    public override double CalcularArea()
    {
        return Lado * Lado;
    }
}

Ejemplo Complejo: Sensores Hardware

Tienes múltiples sensores en un proyecto IoT. Todos son "Sensores", pero un sensor de humedad procesa el voltaje analógico de manera totalmente distinta a uno de temperatura.

public abstract class Sensor
{
    public string Pin { get; set; }
    public abstract double LeerDatoAnalogo();
}

public class SensorHumedad : Sensor
{
    public override double LeerDatoAnalogo()
    {
        // Lógica específica de humedad (Fórmulas)
        return 45.5;
    }
}

Ejercicios: Abstracción

  • Básico: Crea la clase abstracta Animal con el método abstracto HacerSonido(). Crea clases hijas Perro y Gato que implementen el sonido correspondiente.
  • Complejo: Crea una clase abstracta Enemigo con un método Atacar(). Crea clases Mago y Orco. En el main, mete varios en una lista genérica y haz que ataquen en bucle.
// Pista para el complejo (Polimorfismo en acción):
List<Enemigo> horda = new List<Enemigo>();
horda.Add(new Orco());
horda.Add(new Mago());

foreach(var enemigo in horda)
{
    enemigo.Atacar(); // Cada uno sabe cómo atacar
}

5. Interfaces

Contratos de Diseño Estrictos

¿Qué es una Interfaz?

Es un contrato de diseño al 100%. Solo dicta reglas y firmas (QUÉ debe hacer la clase), sin proveer ni una sola línea de lógica (CÓMO hacerlo).

La Analogía: El estándar del Puerto USB. A tu computadora no le importa si conectas un mouse, un teclado o un microcontrolador. Mientras el hardware cumpla el contrato físico (tenga la forma y los pines correctos), el sistema operativo lo aceptará.

// Por convención, las interfaces empiezan con 'I'
public interface IConectable
{
    // No hay public/private. Todo es público.
    // No hay cuerpo de código {}. Es puro contrato.
    void ConectarUSB();
    bool ValidarPuerto(string puerto);
}

Estructura Sintáctica

Para "firmar" el contrato, una clase usa los dos puntos : (igual que en la herencia).

Al hacerlo, el desarrollador queda obligado a programar todos los métodos que la interfaz exige. Si falta uno solo, el código no compilará.

public class PlacaArduino : IConectable
{
    // Obligado a programar esto:
    public void ConectarUSB()
    {
        Console.WriteLine("Rx/Tx listos.");
    }

    // Obligado a programar esto:
    public bool ValidarPuerto(string p)
    {
        return p == "COM3";
    }
}

Ejemplo Sencillo

Garantizamos que cualquier clase que firme el contrato pueda guardar datos, sin importar si los guarda en la nube, en un servidor local o en un simple archivo de texto.

public interface IGuardable
{
    void Guardar(string data);
}

public class BaseDeDatos : IGuardable
{
    public void Guardar(string data)
    {
        Console.WriteLine("Insertando en SQL: " + data);
    }
}

Ejemplo Complejo: Múltiples Roles

En C#, una clase solo puede tener UNA clase padre, pero puede firmar MÚLTIPLES interfaces simultáneamente.

Por ejemplo, un controlador PID es un Hardware, pero también necesita conectarse a la Red y generar Reportes.

// Herencia de clase (Hardware) 
// + Contratos (IRed, IReporte)

public class ControladorPID : Hardware, IRed, IReporte
{
    // 1. Código heredado de Hardware
    
    // 2. Implementar métodos obligatorios de IRed
    
    // 3. Implementar métodos obligatorios de IReporte
}

Ejercicios: Interfaces

  • Básico: Crea la interfaz IGuardable con el método GuardarDatos(). Impleméntala en dos clases totalmente diferentes: ServidorMySQL y ArchivoTexto.
  • Complejo: Crea el sistema IExportable (método GenerarPDF()). Crea clases ReporteFinanciero y KardexAcademico que la implementen. Crea un método estático que reciba la interfaz como parámetro e imprima el documento.
// Pista para el complejo (Desacoplamiento):
static void ImprimirDocumento(IExportable doc)
{
    // Al sistema no le importa de qué clase viene,
    // confía ciegamente porque firmó el contrato.
    doc.GenerarPDF(); 
}
